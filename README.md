# ポケユナ大会サイト

Node.js 24 / Express / Socket.IO / PostgreSQL。参加チームはA〜Jの10チーム固定です。

## 起動

`pnpm install` の後、`DATABASE_URL` を設定して `pnpm start`。
本番では `NODE_ENV=production` を設定します。起動時に必要なテーブルを作成します。
Railwayのヘルスチェックは `/healthz`、起動ポートは `PORT`（既定8080）です。
Socket.IOとルーム内の更新順序を単一プロセスで管理するため、レプリカは1で運用します。

## 操作

- URLの `?room=名前` ごとに選手・ドラフト・設定・トーナメントを分離します。
- 管理メニューは指定の固定パスワードで毎回認証します。タブを離れる・通信が切れると管理権限を解除します。
- チーム名、各チームのドラフト用パスワード、ランク帯、ポイントを管理画面で保存します。登録済み選手のポイントも更新します。使用中のランクは先に選手のランクを変更してから削除・改名してください。
- 抽選は未抽選チームから1チームずつ選び、選択した枠へ登録します。枠1〜6が1回戦シード、枠7〜10が1回戦から出場します。
- 10枠確定後、管理画面で第1試合から得点を入力して保存します。2勝で自動進出し、2–0のときは第3試合を空欄にします。同点、片側のみ、飛ばし入力は保存できません。
- スコアを訂正して対戦相手が変わると、該当する後続試合の結果を解除します。全欄を空欄にして保存するとその試合の結果を取り消します。
- 観戦用トーナメント表は読み取り専用でリアルタイム更新します。管理操作はサーバー側でも認証します。
- 既存の選手操作パスワード `ACTION_PASS` と、ドラフトの開示→一斉進行の方式は継続します。

## 検証

`pnpm test` でBO3・BYE・結果訂正の単体テストと、PostgreSQL互換のインメモリDBを使うSocket.IO結合テストを実行します。結合テストは本番DBを使用しません。実DBのDDL・接続確認はデプロイ時の起動とヘルスチェックで行います。

ローカルの画面確認のみ行う場合は `node --import ./test/mock-postgres.js server.js` を使用できます。このモードのデータは終了すると消えます。本番の起動コマンドには指定しないでください。
